## 7–9. Loading pipeline, atomic install, cancel/retry

```mermaid
flowchart LR
  intent[Mission launch intent] --> resolve[Resolve definition]
  resolve --> validate[Validate content]
  validate --> visuals[Prepare visuals]
  visuals --> collisions[Prepare collisions]
  collisions --> queries[Install spatial queries]
  queries --> ready[Atomic ready]
  visuals -.->|failure| rollback[Dispose and fail]
  collisions -.->|failure| rollback
  queries -.->|failure| rollback
```

Stages: `resolving` → `validating` → `loadingVisuals` → `loadingCollisions` → `installingQueries` → `finalizing` → `ready` (plus cancel/unload/fail).

Cancellation uses AbortSignal + load generation. Stale completions are rejected. Unload is idempotent.

## 12–14. Visual/collision separation, categories, spatial queries

Visual asset ids never appear as collision authority. Categories map to existing `CollisionGroup` bitmasks (`TERRAIN`, `STATIC_STRUCTURE`, …).

`RapierMissionSpatialQueryAdapter` implements:

- `queryLineOfSight`
- `querySegmentObstructions`
- `queryVisibilitySamples`

Default LOS ignores drone, sensors, decorative; includes terrain/static/subject geometry. Unavailable/stale never means clear.

```mermaid
flowchart LR
  q[Mission query DTO] --> adapter[RapierMissionSpatialQueryAdapter]
  adapter --> filter[Category filter]
  filter --> ray[World raycast]
  ray --> dto[Plain result DTO]
```

## 20–21. Lifecycle, diagnostics, validation

Lifecycle: unloaded → resolving → validating → loadingVisuals → loadingCollisions → installingQueries → ready → unloading → unloaded.

`LocationRuntimeDiagnosticsService` reports object/collider/query readiness (non-authoritative).

Failure codes include `LOCATION_PACKAGE_NOT_FOUND`, `LOCATION_CONTENT_INVALID`, `LOCATION_COLLISION_BUILD_FAILED`, `LOCATION_QUERY_INSTALL_FAILED`, `LOCATION_LOAD_CANCELLED`, `STALE_LOCATION_GENERATION`, `MISSION_CAPTURE_NOT_ENABLED`, etc.
