# v1.2.0 Playable Drone Builder

Product surface for Simple and Advanced Drone Builder, local IndexedDB persistence, immutable compiled revisions, Hangar library sections, and exact compiled-aircraft flight launch.

## Architecture

- **Shared Builder session** — Simple and Advanced modes edit the same draft. Mode switches never create a second build and do not dirty selections.
- **Engineering pipeline** — Catalog, compatibility, solvers, and compiler live under `packages/@fpv/*`. The UI maps that output; it does not invent a second flight model.
- **Persistence** — Drafts and compiled revision artifacts are stored on-device via IndexedDB (`DroneBuildPersistenceService`). Cloud sync is out of scope.
- **Hangar sections**
  - Factory Aircraft — original catalog craft
  - User Build Drafts — editable local drafts
  - Compiled User Aircraft — immutable flyable revisions (including orphans after draft delete)
- **Exact flight launch** — Compile & Fly / Hangar Fly select through `SelectedAircraftService.trySelectExact` using the persisted aircraft id. No silent factory fallback.
- **Flight runtime** — Builder/Hangar use the shared `FlightControllerService`. Body-frame Pitch/Roll after yaw is the mainline flight hotfix from PR #6 (`afe6438` / merge `2a5149f`).

## Persistence and recovery

| Situation | Behavior |
|---|---|
| Normal save | Status: “Saved locally on this device” |
| Storage unavailable | Session-only memory backend; clear warning; factory aircraft still work |
| Missing component revision | Draft preserved; compile blocked; category identified; repair by selecting a replacement |
| Unsupported schema | Record preserved; Hangar does not crash; Compile/Fly blocked |
| Delete draft | Confirmation required; compiled revisions remain flyable and labeled orphan |
| Multi-tab | Last-write-wins; no live merge |

## Component media

Product-generated category illustrations (not manufacturer photography). Broken assets fall back to category artwork. Thumbnails are distinct from large detail assets.

## Propulsion data honesty

Engineering estimates use curated synthetic / component-hint provenance. UI never labels synthetic sources as measured commercial fidelity.

## Frame Debug diagnostics

Development builds may toggle a body-frame Frame Debug HUD with **B** when `environment.diagnosticsVisible` is true. Production sets `diagnosticsVisible: false`, so the HUD is off by default and the B shortcut is inactive. Diagnostics APIs used by automated tests remain available.

## Known limitations

- Local-only saves (no cloud)
- IndexedDB behavior differs by browser
- Multi-tab editing is last-write-wins
- Synthetic propulsion data
- Generated component illustrations
- Runtime-version compatibility can mark older compiled revisions non-flyable until recompile
- Mobile: browse/build is supported; ranked stick flight may warn when controls are inadequate
- Developer Frame Debug is development-gated only

## Manual smoke checklist

1. Create → rename → change part → Save → refresh → Hangar → reopen (same id/name/intent/parts)
2. Duplicate draft (new id; independent after rename)
3. Factory → Duplicate into Builder → change part → save (factory unchanged)
4. Compile Revision A → change engineering part → Compile Revision B (A immutable; both in Hangar)
5. Fly A and B separately (exact aircraft id; body-frame controls)
6. Delete draft → orphan revision still flyable → Duplicate/Rebuild
7. Missing component + unsupported schema recovery
8. Storage unavailable banner and session-only wording
9. Responsive: ~1440 / 1280 / 1024 / 768 — no horizontal overflow
10. Keyboard focus on dialogs and mode switch
